## Cómo se llena el canvas

No de izquierda a derecha. En este orden:

| # | Bloque | Pregunta |
|---|---|---|
| 1 | Segmentos de clientes | ¿Quién es, con industria, tamaño y ciudad? ¿Quién usa y quién paga? |
| 2 | Problema | Tres dolores. El principal, en pesos o en días. |
| 3 | Propuesta única de valor | ¿Qué cambia la semana que entra? |
| 4 | Solución | Un verbo por cada dolor. |
| 5 | Canales | ¿Cómo llegan a los primeros diez? |
| 6 | Flujos de ingreso | ¿Quién paga, cuánto, contra qué? |
| 7 | Estructura de costos | ¿Qué cuesta una sola operación? |
| 8 | Métricas clave | ¿Qué dos números dirían si el piloto funciona? |
| 9 | Ventaja injusta | ¿Qué no copian en 30 días? |

Regla: si una casilla no cabe en una frase corta, está incompleta. Se recorta, no se adorna.

Plantilla: [`plantillas/lean-canvas.md`](plantillas/lean-canvas.md)  
Canvas en sala: [`presentaciones/canvas.html`](presentaciones/canvas.html)

## Lo básico de Stellar

Stellar es una red para **mover valor** (pagos, USDC, liquidación) y **dejar un registro** que varias partes pueden verificar. El costo de la red es marginal; el costo que define el margen es **convertir a pesos**.

No hay que encajar la idea a la red. Si el cliente se resuelve con Excel y SPEI, se dice. Guía corta: [`stellar.md`](stellar.md).

## Cómo entregar

Todo desde el navegador. Un fork por equipo.

1. Abrir [github.com/MarxMad/Ideathon-Stellar-BAF-Canacintra](https://github.com/MarxMad/Ideathon-Stellar-BAF-Canacintra).
2. Arriba a la derecha: **Fork** → **Create fork**.
3. La URL debe decir `github.com/SU-USUARIO/Ideathon-Stellar-BAF-Canacintra`.
4. En ese fork: **Add file** → **Upload files**. Suben `lean-canvas.md` y `pitch.md` a `ideas/equipo-07-nombre-corto/`.
5. **Commit changes**.
6. **Contribute** → **Open pull request** hacia el repo original.
7. Título: `Equipo 07 — Nombre de la idea`.

Diapositiva de sala: [`presentaciones/04-git.html`](presentaciones/04-git.html).
